Systems design · Case study

Agentic AI Operations Orchestrator

A multi-workstream assistant system designed to route work to specialist owners, retrieve current state from canonical services, verify changes, and preserve human approval for consequential actions.

In progress: rollout validation remains partial

The problem

Long-running career, content, personal, and migration workflows were spread across chats, files, trackers, repositories, email, and calendars. Conversational memory alone was not a dependable system of record. The design needed clear ownership, duplicate avoidance, safe approvals, and durable continuation across devices.

Architecture

OwnerIntent and consequential approvals
Master OpsArchitecture, routing, blockers, verification
SpecialistsMigration Ops · Content Ops · Unified Ops
Canonical toolsNotion · Drive · GitHub · Gmail · Calendar

Workers retrieve source state, check for duplicates, execute bounded work, read back changes, write a durable checkpoint, and continue with the next executable task. A blocked branch is recorded while independent work continues.

Key decisions

  • Use one coordinator with bounded specialist and recurring execution roles.
  • Assign each kind of data a canonical owner instead of relying on chat history.
  • Separate preparation from external commitments through explicit human approval gates.
  • Distinguish configured, connected, read, write, read-back, and real-run evidence.

Verified outcomes

  • Completed and froze the source inventory through the final migration phase while preserving source material.
  • Verified live reads of Gmail, Drive, GitHub, and Calendar; a temporary Calendar create/read/delete test passed.
  • Verified Notion operational access and a human-facing home built from linked views of existing databases.
  • Completed a phone-to-desktop continuity check, as reported by the owner.
  • The recurring operator’s first run avoided one checked duplicate, but full branch-level write-back and validation remain partial.

Limitations

  • Extra destination Projects remain; consolidation is incomplete.
  • Some Notion view rows were not visible in the captured UI.
  • Recurring operator branches have not all passed independent real-run validation.
  • No custom agent runtime, workflow engine, MCP server, vector RAG pipeline, or tracing backend was implemented.
  • No measured productivity, revenue, or benchmark claims are made.

Production next step

Rebuild the workflows as typed, persistent state machines with atomic idempotency, scoped tools, bounded retries, approval records, structured traces, deterministic tests, and sandboxed integration tests. Measure completion, duplicate rate, latency, cost, and human intervention before claiming improvement.
